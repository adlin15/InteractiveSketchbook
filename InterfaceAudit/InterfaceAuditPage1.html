Interface Audit

When I look at my micro-project landing page, I see that all my elements, which are underlined blue words are shoved to the right side, and the rest is just a blank empty space page. There is no indication that there are instructions or any indicators of any system statuses. So far, one can assume that this could be a base stage, where no interactions happen until you click on the underlined blue linked sources that leads to the website/code. This is the only action that you would see on the micro-project page where you can click and it redirects the user to the page of what is written, one example being the self-assessment I wrote that shows typefaces in paragraphs. It is unclear, direction wise on how you would encounter this without randomly clicking the entire page until something works, if you were someone who never used a computer before. The landing page layout hierarchy is also not apparent, as all the text sizes are of the same sizes. There is no way of telling which part is important besides reading the names of the underlined words. There is also no rewind button, to return back to the previous page with the exception of the < icon on the top corner of the website. The two heuristic violations that are apparent in the landing pages are Visibility of System Status, and Match Between the System and the Real World. Currently, there is no status or indicator that displays the current system status, and there aren't many predictable interactions that inform the users of the current status. One structural fix for this would be to make the landing page have a colored status quo on a sidebar next to each of the possible linked elements, with green showing that the servers were previously edited, and red showing no changes or unavailable. This way, I can communicate clearly with users of system statuses, and this is my potential solution to this problem. The second problem is matching visually with the systems to the real world, as in making the system match with how users would want by following real world conventions, such as ensuring that users can understand what they are looking at, even if it's currently an empty blank page. We aren't used to reading on the left side for information, we read left to right, so logically to fix this issue, I should put the text as aligned from left to right, or leave it at the center of the page so it's easily readable. Three structural changes I should make to these pages is to add a clear hierarchy to all the texts and elements to make each part stand out of its purpose, make navigation bigger and easier to access by adding a large button, and lastly add other interactables to give visual clarity and not make every single underlined blue link have this weird file icon that only shows up when on laptop, and it also shows up to be horizontal instead of vertical for the landing page.
